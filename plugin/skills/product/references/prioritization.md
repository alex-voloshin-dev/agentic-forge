# Prioritization frameworks & product metrics (product reference)

Load when the ask involves *ordering* the work (what to build next, MVP scope, roadmap) or
*measuring* it (success metrics for the PRD) — not for writing the requirements themselves.

## Pick the framework by the data you have

| Framework | Mechanics | Reach for it when |
| --- | --- | --- |
| **RICE** | Reach × Impact × Confidence ÷ Effort → one score | You can estimate how many users each item affects (quantitative data exists) |
| **ICE** | Impact × Confidence × Ease | Early stage / no reach data; you need a fast, defensible ranking |
| **MoSCoW** | Must / Should / Could / Won't buckets | Scope negotiation, release planning, MVP definition — stakeholders need buckets, not scores |
| **JTBD** | "When I [situation], I want to [motivation], so I can [outcome]" | The team is unsure what users are actually hiring the product to do — run this *before* scoring |
| **Kano** | Basic / Performance / Excitement | Balancing hygiene (bugs, table-stakes) against differentiators |

Recommend one, explain why, and show the scoring — do not mechanically apply all five. Inputs
(reach numbers, effort estimates) follow the evidence discipline: sourced or explicitly marked
as estimates.

## Metric frameworks (for the PRD's success-metrics section)

- **North Star** — the one metric that captures delivered value; everything else supports it.
- **AARRR** — Acquisition, Activation, Retention, Revenue, Referral; pick the stage that the
  feature actually moves.
- **Input vs output** — pair each lagging outcome (retention) with the leading input the team can
  act on (activation rate, time-to-value).
- **AI-product specifics** — model quality ≠ product success: also track user-facing error /
  fallback rates, trust/adoption curve, and time-to-value of the AI feature.
- Prefer actionable metrics over vanity counts (cumulative signups tell you nothing to do next).

## Roadmap shape

For early-stage: **Now (0–4 wk) / Next (1–3 mo) / Later (3–6 mo)**, each initiative under a
strategic theme with its success metric, rough effort, dependencies, and risks. Quarterly horizons
for mature products. Outcomes over features: name the change in user behavior, not just the
deliverable.
